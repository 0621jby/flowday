## 审查边界

已检查工作区，无代码或 PRD 文件。证据来自本次需求描述。下列“遗漏”指当前描述未规定，并不声称原 PRD 一定缺失。对原数据库字段、代码质量、依赖版本与漏洞的审查暂不能完成。

## 严重问题

| 问题/证据 | 商业或工程后果 | 具体改进 |
|---|---|---|
| 目标市场只有“大众用户” | 学生、管理者、自由职业者的预算、时间控制权和需求冲突 | 先聚焦有自主时间、每周推进个人项目的人；访谈 15 人，试用 30 人 |
| 功能横跨任务软件、日历、教练、目标管理、统计 | MVP 成为大而不精的待办工具，无法判断谁愿付费 | 首发只验证“计划落空后的恢复执行”，其余功能分期 |
| AI 主动指导尚无可观测触发依据 | 无法知道用户离线是否已工作，误判拖延损害信任 | 状态只称“尚未记录开始”；先询问，再建议；支持补记 |
| “两个月学会 Python”没有成果、时间预算或基础定义 | AI 生成看似合理但做不完的计划 | 先澄清每周时间、已有能力、Web 项目验收；容量不足应明确反对截止日期 |
| 计划、任务状态、执行事实未明确分离 | 自动挪动时间可能误改完成状态，统计失真 | 任务为意图，时间块为预约，执行事件为事实；三者独立 |
| 商业主体、市场、部署地区未定 | 后期重做支付、模型和数据存储 | 商业化前先定市场与合法可用供应商；禁止同时承诺全球与大陆体验 |

## 重要问题

| 问题 | 改进 |
|---|---|
| 页面数量被当成功能优先级 | 今日、规划、执行、复盘构成一个连续流程；AI 先以情境卡片出现 |
| 无限 AI 聊天可能成本高且缺乏付费价值 | 对规划、受阻拆解、复盘提供有界调用；通用聊天降级为后续能力 |
| 过早自动重排会破坏控制感 | 默认只预览差异，保护进行中、锁定和临近时间块；确认后应用 |
| “越多提醒越有效”没有依据 | 默认每日最多 2 条主动教练提醒，最少 120 分钟间隔；主动关闭也算质量信号 |
| 层级目标和任务可能重复 | 目标定义结果，里程碑定义验收点，只有叶子任务参与排程；不独立复制子任务表 |
| SaaS 运营要求不具体 | 加入退款、失败续费、数据导出删除、客服、恢复演练、审计、反滥用与告警 |
| 日历同步很容易被低估 | MVP 手工固定日程；随后单向读忙闲；最后才做可撤销的外部写入 |
| 完成率可被拆小任务刷高 | 同时测重要任务推进、原始承诺完成率、开始延迟和主观帮助度 |
| 重复任务/时区未定义业务语义 | 系列与实例分开；IANA 时区、当地日期与 UTC 时间点分开；DST 明确策略 |

## 一般优化建议

- 快速添加只要求标题；日期、目标、预计时长可后补。未知时长进入待估算，不擅自填满日历。
- 不做“执行力分数”、排行榜、羞辱式连续打卡或医学化人格判断；缺少可验证收益，且容易制造负担。
- 不把“AI 教练”固定为主导航核心入口；先验证上下文卡片能否解决开始困难。
- 不在第一版开发团队权限、甘特图、原生 App、多 Agent 自治、向量数据库、复杂积分商城。
- 计时器可选；用户可以直接完成和补记，不能强制计时才算工作。
