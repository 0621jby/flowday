# MVP 实现与后续交接

日期：2026-11-18。用户已授权从架构设计进入MVP开发。本阶段交付本地可用版本；原路线图未全部完成，不把本地MVP等同P1–P5全部验收。

## 已落地的产品闭环

我的一天 → 新建/编辑任务 → 生成计划并确认 → 开始专注 → 暂停/受阻小行动 → 完成 → 每日复盘 → 洞察。桌面侧栏与手机底部导航共享状态；弹窗支持Esc、焦点限制、表单标签。示例数据仅用于体验，不代表真实用户表现。

实现保留 `WorkspaceRepository` 边界、Zod数据契约、纯函数调度器和独立规则教练。视觉采用浅灰绿工作台、深绿当前任务卡、轻量时间/容量反馈；无图片/外部素材依赖。

## 与设计基线的范围差异

| 设计能力 | 当前实现 | 后续工作 |
|---|---|---|
| PostgreSQL/Supabase/RLS | 浏览器本地repository | Auth、服务端actor、RLS、复合FK、事务、版本控制 |
| 跨设备一致性 | 同浏览器标签页同步+非原子版本检查 | 服务端事务和幂等，不宣称目前支持多设备 |
| 完整调度引擎 | 单日/不可拆/优先级/容量/缓冲/预览 | 固定日程、依赖DAG、时区/DST、锁定、跨日、版本历史 |
| AI Coach | 显式标记规则版，用户确认才创建小行动 | 模型adapter、预占额度、提案hash、服务端审批执行 |
| 执行记录 | 开始/暂停/经过时长/完成重开事件 | 服务端会话、异常挂机修正、执行段与补记 |
| 每日复盘/分析 | 本地实际记录汇总 | 原始承诺分母、估时偏差、数据充足性评估 |
| 商业化 | 未接入、不显示购买按钮 | 支付沙盒、webhook、权益账本、取消退款 |
| 数据生命周期 | JSON导出，浏览器持久化 | 导入、服务器导出删除、备份恢复与审计 |

## 建议给后续开发者的顺序

1. 保留可用界面，按功能逐步拆分 `workspace.tsx` 的各视图与弹窗，不先重写全站。
2. 建立 Supabase 本地/测试环境，实施 profiles、tasks、goals、execution 与RLS测试；将repository替换为鉴权API适配，禁止前端保存service_role。
3. 把保存/执行/计划提交从组件内命令提升到application用例；服务端验证expectedVersion、幂等键与所有权。
4. 加计划修订历史、固定忙碌与可靠时间计算；再做重复任务和日历读取。
5. 接模型服务和配额，将当前规则教练作为稳定降级路径；重要写入仍在用户确认后由服务端执行。
6. 最后接支付和上线运营；本地版本不能收集真实付费或承诺云端备份。

## 已知限制

- 当前导航为单页视图切换，不支持各视图独立URL/深链。
- 示例任务初始安排在首次打开当天，跨日后不会自动迁移，须手动编辑日期。
- 尚无完整任务审计快照、目标编辑删除、数据导入及离线冲突合并。
- 此版本的任务数进度只表示行动完成量，不表示目标实际成果进度。
- 不使用未经确认的模型输出；规则建议无需外部网络，也不消耗AI额度。
