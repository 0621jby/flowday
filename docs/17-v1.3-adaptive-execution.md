# FlowDay V1.3 自适应执行与成长

V1.3 把执行记录、跨日调整、个性化估时和成长报告交付在同一个版本。排程和统计由程序计算。AI 解读使用原有教练入口与调用配置。

## 如何体验

1. 运行 `npm run dev`，打开 `http://127.0.0.1:3100`。本地工作区可以直接升级并继续使用现有浏览器数据。
2. 在任务详情展开“任务类型、截止日期与依赖”。任务的计划日期和截止日期分开保存。选择类别后，有足够同类样本时可以将建议估时填入表单，再保存。
3. 从今日工作台开始任务。暂停、继续、结束和完成都会记录时间。任务详情的“执行记录与后续安排”展示历史，也可放弃或恢复任务，或者将大任务显式拆分成 2–6 步。
4. 在个人设置录入临时可用时段、容量和午休、会议等固定日程。今天没有时间时，可把当天容量设为 0。已确认的预约会留在日历中，冲突由排程预览指出。
5. 在今日工作台或计划日历选择“自适应排程”。选择今天、3 天、7 天或 14 天，可指定临时优先任务、额外预留分钟或主动延期一项。先查看前后安排、调整理由和未排入的任务，再确认保存。
6. 在数据洞察查看每日、7 日、30 日或 90 日报告，并选择统计截至日期。报告与前一个等长周期对比，展示预约日完成、专注、活跃天数、延期、估时偏差以及类别和时段分布。
7. 如希望 AI 解读周月趋势，在个人设置勾选“允许 AI 读取成长统计摘要”。计划预览也可打开 AI 解读。生成由用户点击触发，真实模型沿用原有启用开关。配置步骤见 [V1.2 模型配置](16-v1.2-ai-coach.md)。

## 计算和数据含义

- 执行中和暂停由当前专注会话决定。待开始、完成、延期和放弃结合任务状态、计划日期与操作历史显示。延期次数统计实际向后改期，计划日经过但未改期的任务只显示逾期状态。
- 执行经过时间包含同次计时中的暂停。记录专注时间仅累加计时运行片段。它依赖用户手动开始、暂停和结束，后台计时无法识别注意力。旧记录继续贡献专注和完成统计。
- 个性化估时至少需要过去 90 天内 5 项不同的同类完整计时任务，且原估时与当前任务处于相近量级。建议取记录专注分钟的中位数并按 5 分钟取整。周期估时偏差比较记录时长和开始时的估时。现有历史中无法确认完整性的片段不会参与学习。
- 自适应排程以截止日期和任务优先级排序，指定的临时任务可优先。它检查依赖预约顺序、固定日程、每日可用窗口、容量、休息和缓冲。默认保留已有预约。勾选重排后，锁定、进行中和当前专注任务仍受保护。找不到替代时段时保留原预约并提示原因。确认时重新检查版本和时间。
- 原任务及其历史在拆分后保留，子任务按顺序依赖、分别预约，完成全部步骤后可将原任务标记为完成。拆分属于一次显式创建操作，后续跨日排程单独预览确认。
- 预约日完成率基于新版记录的原始确认日期。当天尚未结算，旧版未记录的承诺无法补算。时段统计按记录结束时刻归类，用于观察分布。它无法单独证明工作效率或行为原因。
- 成长统计的 AI 分享默认关闭，复盘文字仍需单次授权。服务端会话如已登录，只能读取当前账户。关闭个性化时停止使用历史生成估时和负荷建议，原始记录仍可在本账户查看与导出。

## 云端升级与验证

已有云端工作区需在 Supabase 开发数据库执行 [003 迁移](../supabase/migrations/202611190003_adaptive_execution.sql)。新项目按 001、002、003 顺序执行。V1.3 在现有版本事务中保存扩展字段与追加式执行历史。旧版本页面不能把新版历史覆盖为旧结构，新版写入也会在旧数据库上先失败再提示迁移。本地模式无需新的环境变量。

主要实现位置为 [执行记录](../src/modules/core/execution.ts)、[多日排程](../src/modules/planning/adaptive.ts)、[成长统计](../src/modules/core/growth.ts)、[交互界面](../src/components/adaptive-execution.tsx)和 [Coach 上下文](../src/modules/coach/context.ts)。

本地验证覆盖新增执行、排程、成长统计、数据库读取隔离、历史回滚保护和界面确认流程。托管 Supabase 和真实模型通信需使用对应的开发凭证单独验收。工作区沿用现有 5 MiB 请求上限。更大历史体量需要按页读取和增量保存，目前尚未实现。
