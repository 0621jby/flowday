# FlowDay V1.5 上线配置与验收

V1.5 将现有工作台接到增量云端保存、按需历史、新用户引导、数据控制和可配置账户权益。工程继续使用 Next.js 与 Supabase。默认 Mock 可以在本机直接体验。

## Supabase

1. 新建或选用一个 Supabase 开发项目。空库按顺序应用 `supabase/migrations` 的 001 至 005。已经应用到 V1.3 的项目只需执行 [004](../supabase/migrations/202611190004_saas_workspace.sql) 和 [005](../supabase/migrations/202611190005_saas_controls.sql)。在 SQL Editor 逐份执行，或走项目已建立的 Supabase CLI 迁移流程。已有数据库升级前应保留可恢复的备份。
2. 在项目根目录的 `.env.local` 填入项目 URL 与 Publishable Key，对应 `NEXT_PUBLIC_SUPABASE_URL` 和 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`。保留随机生成的 `AI_PROPOSAL_SECRET`，部署到多个实例时使用同一个值。
3. 在 Supabase 认证启用邮箱与密码。将 `APP_ORIGIN` 和 Supabase Auth 的 Site URL 设成应用访问地址。开发时为 `http://127.0.0.1:3100`，回调白名单加 `http://127.0.0.1:3100/auth/callback`。部署时使用实际 HTTPS 域名及相应回调。生产邮件送达需要在 Supabase 验证邮件配置。
4. 执行 `npm ci` 和 `npm run dev`，打开对应地址，注册并完成邮箱确认。第一次进入空工作区可以设置时段与习惯，创建目标、任务并预览第一份计划。也可跳过。检测到本地数据时，可先从个人设置导入到从未写入的账户。导入保留浏览器原始工作区。
5. 可选配置服务端 `SUPABASE_ACCOUNT_ADMIN_KEY`，使用该项目的 secret 或旧版 service_role，仅在账户删除路由中读取。应用在当前登录账户重新验证密码后调用 Auth 删除。日常读写、清理工作区和 Admin Key 均独立，日常读写只使用用户会话。环境变量示例见 [.env.example](../.env.example)。[Supabase Auth 删除接口](https://supabase.com/docs/reference/javascript/auth-admin-deleteuser)

004 将旧版执行历史拆成独立行并保留任务元数据。业务写入按记录变更执行，旧客户端需要刷新页面。各账户的修订版本、数据库事务、请求回执与 RLS 一起保护数据。待确认的变更可在原标签页重试，使用同一请求编号，回执保留 7 天。发生版本冲突时可导出待保存变更，选择放弃后同步，由用户决定如何处理。页面在前台每 30 秒及重新聚焦或联网时拉取新版本。初始云端加载故障会显示错误，并保留本地原始数据。

历史任务、复盘列表、单日复盘、执行与专注记录按需读取。完整导出时才读取全量数据。日常工作区读取待办、近期完成记录和排程相关任务，独立报告返回服务端的周期统计。累计统计通过写入时更新的汇总表读取。完成图仍以近期任务为数据范围。旧版一次导入仍受 5 MiB 请求上限限制。

## DeepSeek 或兼容供应商

在 `.env.local` 保留你已有的模型密钥和模型 ID，按供应商配置其余字段：

```dotenv
AI_PROVIDER=deepseek
AI_API_URL=https://api.deepseek.com
AI_API_KEY=填入供应商的密钥
AI_MODEL=填入供应商为该密钥开放的模型ID
AI_OUTPUT_FORMAT=json_object
AI_ENABLE_PAID_CALLS=false
```

通过第三方网关调用时，使用该网关提供的 API 根地址或完整 Chat Completions 地址。可设 `AI_PROVIDER=openai-compatible`。输出格式可按供应商能力选 `json_object`、`strict` 或 `plain`，必要时通过 `AI_TOKEN_FIELD` 切换输出长度参数。DeepSeek JSON 模式使用 `json_object` 和 `max_tokens`。[DeepSeek JSON 输出文档](https://api-docs.deepseek.com/guides/json_mode/)

成功登录且准备好允许真实费用时，才把 `AI_ENABLE_PAID_CALLS` 改为 `true` 并重启。维持 `AI_PROVIDER=mock` 可以继续演示。启用真实模型后，用户点击生成才创建请求。Zod 校验每份方案，格式异常最多补发一次请求。可通过 `AI_FORMAT_RETRY=false` 禁用补发。认证错误、供应商限流和网络异常不会触发模型补发。个人设置中的 AI 开关也在服务端检查。建议仍要经过预览和明确确认，模型没有业务写权限。

使用事件按账户记录生成请求、供应商调用次数、Token 和估算费用。单价从 `AI_INPUT_USD_PER_MILLION` 和 `AI_OUTPUT_USD_PER_MILLION` 读取。缺少单价或供应商实际用量时费用标为未知。额度按生成请求计，单次请求最多两次供应商调用。相同请求在短窗口内复用现有结果。后台行为不触发付费模型。

## 权益、隐私与账户控制

- `plan_policies` 配置 Free / Pro 的每分钟与每日 AI 限额、成长报告范围和个性化。尚未分配时默认为 Free。 `account_plans` 由运营者分配，账户无法给自己升级。初始配置给 Free 与 Pro 保留 V1.3 功能，Pro 提供更高 AI 配额。可在数据库中为每一档调整范围，关闭后由服务端执行。权益与将来的价格及支付完全独立。
- 个人设置展示当天（UTC）额度和已知费用。成长统计分享和复盘文字授权与 AI 开关分开。
- 导出包含工作区、历史、计划记录和可用的 AI 记录。输入确认文字才能清理云端工作区，清理保留账号、档位和不含内容的额度记录。永久删除还需重新验证账户密码。原浏览器本地工作区与用户已下载的文件由用户独立管理。
