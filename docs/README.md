## 建议批准的基线

- 首批用户收窄到“有自主安排时间、正在推进一个学习或个人项目的知识工作者”。大众市场是远期方向。
- 核心闭环为计划 → 开始 → 受阻恢复 → 完成/调整 → 复盘。衡量有效推进，不能用聊天次数证明产品价值。
- 模块化单体：Next.js + TypeScript + PostgreSQL/Supabase；同仓后台 worker，确定性排程，AI 只提出受控方案。
- 第一版只做个人账户、手工固定日程、单日计划、执行记录、受阻帮助、有限重复任务、基础订阅。先验证再做双向日历同步和深度个性化。
- 所有业务写入经后端用例执行；AI 不持有数据库凭据；用户确认绑定操作摘要、对象版本、有效期。
- 暂按 2 名全栈工程师、1 名兼职产品/设计、国际单一区域部署估算。预算、主体所在地、首发市场尚未确认；中国大陆首发不能直接套用支付和部署假设。

## 待确认的决策与验证条件

| 决策 | 当前建议 | 不确认的影响 |
|---|---|---|
| 首发市场/经营主体 | 国际版技术基线，中文界面优先 | 支付可用性、数据区域、模型可用性无法最终确定 |
| 首批用户 | 自主项目执行者 | 无法统一 onboarding 和获客文案 |
| 范围 | 先闭环、后集成 | 同时开发所有页面会拖延验证 |
| 原始 PRD | 补充后做逐条映射 | 无法判断原表字段与功能的实际缺陷 |
| 收费实验 | $8/月与 $12/月测试，初始建议 $9/月 | 价格只是待验证假设 |

本文档中的 SLO、价格、实验门槛和工期是设计目标。`docs/sql` 中 SQL 是未实施的原始草案；`supabase/migrations` 是已通过本地 PostgreSQL 测试的 V1.1 实际迁移，尚未应用到远程项目。
